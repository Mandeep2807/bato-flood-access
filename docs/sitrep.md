# One-page SITREP from the official result

| | |
|---|---|
| Generator | `src/bato/dashboard/sitrep.py` (`load_facts`, `render`, `write_report`) |
| Script | `scripts/build_sitrep.py` |
| Output | `reports/BATO_SITREP.md` (default; `--output` to change) |
| Tests | `tests/unit/test_sitrep.py`, `tests/integration/test_sitrep_script.py`, `tests/integration/test_sitrep_real_data.py` (opt-in) |

The SITREP is **system-generated by a deterministic template**. The wording is fixed; the numbers, dates and
identifiers come from the official result files. It is **not** an AI component, and it is **not** an assessment of
current conditions: the observation time is the Sentinel-1 POST pass, and the issue time is when the report was
generated. Both are printed, together with the number of days between them.

## 1. Run

```bash
M=data/raw/manifests/aoi-e893707c2beb_fetch_manifest.json
python scripts/build_sitrep.py --manifest $M --title "Trishuli Flood, Nepal" \
    --incident "flood, Bhote Koshi–Trishuli corridor (Rasuwa/Nuwakot), Nepal" \
    --prepared-by "404 Competition Not Found"
```

Options:

| Option | Effect |
|---|---|
| `--issued-at 2026-10-13T07:00:00Z` | Fixes the issue time. The output is then byte-identical on every rebuild. The default is now (UTC). |
| `--local-tz Asia/Kathmandu` | Adds a local clock time next to the UTC issue time. This makes the header line longer, so check the page fit. |
| `--connectivity-dir <dir>` | Selects a connectivity run explicitly. It must be a road rule v1 run. |
| `--number 2` | Sets the SITREP number. |
| `--output <file.md>` | Changes the output file. Raw, interim and evaluation-only folders are refused. |

`--title` and `--incident` are required descriptive text. They are not read from the data, because the result files
do not name the incident.

Print with the Markdown PDF extension at `"markdown-pdf.scale": 0.9`, the same setting as the technical report.
At that setting the official SITREP fits one A4 page.

## 2. Which files, and what is checked

The official run is found exactly as for the dashboard, using the unchanged `bato.dashboard.bundle` functions:
- the latest connectivity run with `road_rule: v1` is used; a `.superseded-*` directory counts;
- a road rule v2 run is refused;
- every output must match the SHA-256 in its provenance;
- the stack and Step 4C provenance files must match their recorded hashes;
- the provenance summary must equal the counts recomputed from `road_segments.geojson` and `settlements.geojson`.

| Printed value | Source | Extra check (any failure stops the run; nothing is written) |
|---|---|---|
| Blocked / observed-open / unobservable segments and km | `connectivity_provenance.json` summary | Equal to `road_segments.geojson`; km within 0.001 |
| Blocked stretches | summary `blocked_stretches` | Equal to the entries of `blocked_segments_ranked.json`, whose segment lists partition the BLOCKED segments exactly |
| Settlement access counts | summary `settlements_by_access_state` | Only the four known states; they sum to the total and agree with the reachable counts of the pre-event, optimistic and pessimistic graphs |
| Share of scene not assessed, and the reasons | Step 4C provenance `statistics` | Assessed + not assessed = total; the NOT_ASSESSED reasons sum to the not-assessed count; the published fraction matches |
| "Provisional thresholds, not validated" | Step 4C and connectivity provenance | Every threshold is provisional, and both files state `validated: false` |
| Event, area, buffer, passes, track, OSM snapshot | connectivity / stack provenance | Same event, AOI and candidate everywhere; PRE-1 < PRE-2 < POST; one track; one Sentinel-1 unit; snapshot before the event |

**Fixed text.** The EMSR927 sentence and the Step 4C limitation sentence are fixed. By the data rules, presentation
code never reads `data/reference`, `data/eval` or the evaluation protocol.
- The EMSR927 sentence restates the frozen protocol `bato-emsr927-v1` and section 7 of the technical report.
- It is printed only for the run that the protocol evaluated (`aoi-e893707c2beb` / `ts-80841ae62417`).
- Any other run instead gets "Reference comparison: none for this run", and no EMS credit.

The attribution lines come verbatim from `bato.attribution`.

## 3. Limits

- The SITREP repeats the official result; it adds no new measurement.
- It does not estimate population, casualties or forecasts.
- It does not describe conditions after the POST pass.
- The verification priorities are fixed rules applied to the published counts. They are not a learned or optimised ranking.
